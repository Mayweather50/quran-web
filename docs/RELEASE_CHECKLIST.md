# Release checklist

## До покупки VPS

- Репозиторий на GitHub обновлен.
- В проекте нет настоящих паролей и токенов.
- Выбран VPS с Ubuntu, IPv4 и минимум 1 GB RAM.
- Выбран домен.

## Backend

- `backend/.env` создан из `backend/.env.production.example`.
- `NODE_ENV=production`.
- `CURRENT_USER_ID=` пустой.
- `ALLOW_FILE_ORIGIN=false`.
- `JWT_SECRET` длинный и случайный.
- `FRONTEND_ORIGIN` содержит только реальные домены.
- `npm run migrate` выполнен.
- `npm run seed` выполнен один раз, если нужны стартовые данные.
- `npm run preflight` проходит без ошибок.
- `curl http://127.0.0.1:3001/api/health` возвращает `status: ok`.

## Frontend

- На VPS файл `_config.js` содержит:

```js
window.__API_BASE__ = '/api';
```

- `index.html`, `booking.html`, `schedule.html`, `teachers.html`, `profile.html`, `admin.html` открываются через домен.
- В DevTools Network нет запросов к `localhost`, Netlify или Render после полного переезда.

## Nginx и домен

- `/api/health` работает через домен.
- `https://domain` открывает главную.
- `https://domain/booking` открывает запись.
- `https://domain/schedule` открывает расписание.
- SSL выпущен через Certbot.
- HTTP автоматически перекидывает на HTTPS.

## Ручная проверка функций

- Регистрация ученика.
- Вход ученика.
- Запись ученика на доступный слот.
- Повторная запись на то же время блокируется понятным сообщением.
- Много учеников могут записаться к одному преподавателю на одно время.
- Гость может смотреть главную, преподавателей, запись и расписание.
- Ученик видит свои записи в профиле.
- Преподаватель видит и редактирует свои слоты.
- Админ видит учеников, преподавателей, записи, группы, расписание.

## После релиза

- Демо-пароли заменены.
- Лишние демо-пользователи удалены или отключены.
- Сделан первый backup БД.
- Сохранены доступы: VPS, домен, PostgreSQL, GitHub.
